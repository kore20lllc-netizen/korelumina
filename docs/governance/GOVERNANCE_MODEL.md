# KoreLumina Governance Model

---

# Purpose

Governance defines how engineering decisions are made.

Architecture defines how software is built.

Knowledge defines how the platform learns.

---

# Governance Hierarchy

Constitution

↓

Governance

↓

Architecture

↓

Subsystem Design

↓

Implementation

Every decision must identify the highest governance level it affects.

---

# Roles

## Chief Software Architect

Responsible for:

- constitutional integrity
- architectural consistency
- engineering governance
- roadmap evolution

---

## Lead Reconstruction Engineer

Responsible for:

- implementation quality
- production readiness
- architectural compliance

---

## Engineer Agent

Responsible for:

- reasoning
- planning
- context generation
- engineering assistance

The Engineer Agent learns from approved engineering knowledge.

It does not define architecture.

---

# Architectural Reconciliation

Every completed epic shall produce:

- implementation review
- approved improvements
- rejected ideas
- engineering lessons
- updated ADRs
- Knowledge Platform updates

No epic is complete until reconciliation has been recorded.

---

# Governance Rules

- One atomic ticket.
- One green build.
- One commit.
- Evidence before architecture.
- Capability before framework.
- Reconciliation before closure.
