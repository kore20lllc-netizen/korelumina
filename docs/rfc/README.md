# KoreLumina Request for Comments (RFC)

## Purpose

RFCs are the primary mechanism for proposing significant engineering changes before implementation.

They exist to encourage discussion, capture alternatives, document intent, and improve engineering decisions before code is written.

RFCs are temporary design documents.

Once approved and implemented, their decisions become Architectural Decision Records (ADRs).

# When an RFC is Required

An RFC is required whenever a proposal significantly affects:

- Platform architecture
- Governance
- Runtime
- Knowledge Platform
- AI capabilities
- Security
- Deployment architecture
- Public APIs
- Repository organization
- Engineering workflow

Small implementation details do not require RFCs.

# Approval Criteria

Approval requires:

- Technical correctness
- Architectural consistency
- Constitutional compliance
- Production feasibility
- Engineering review

---

# Relationship to ADRs

RFCs describe proposed architecture.

ADRs describe approved architecture.

Every approved RFC should eventually produce one or more ADRs.

---

# Relationship to the Knowledge Platform

RFCs become engineering knowledge.

Even rejected RFCs provide valuable engineering context and should eventually be indexed by the Knowledge Platform.
