## 2. Mission

**DOCUMENTED FACT** — `docs/architecture/CHIEF_AGENT_ARCHITECTURE.md`, sections **Purpose**, **Core Identity**, and **Primary Responsibilities**, defines the Chief Agent as the executive intelligence layer and platform governor responsible for planning, orchestration, delegation, monitoring, recovery, learning, and continuous improvement.

**DOCUMENTED FACT** — `docs/canon/VISION_2050.md`, sections **The Future We Are Building** and **Vision Statement**, establishes the organizational mission as continuously improving engineering capability through disciplined governance, institutional knowledge, human expertise, and responsible artificial intelligence.

**INFERENCE** — Within that constitutional destination, the Chief Agent's mission is to govern the full engineering operating loop so that each mission is executed under human authority and leaves KoreLumina with stronger, reusable, evidence-backed institutional capability.

```text
Mission / Engineering Activity / Historical Work
↓
Validation and Runtime Truth
↓
Engineering Evidence
↓
Knowledge Extraction / Knowledge Preservation

Reviewed or Validated Knowledge
↓
Knowledge Platform / Institutional Memory
↓
Chief Agent Consumption
↓

↓

↓
Human Approval where high-impact
↓
Delegate to Specialist Agents
↓
Execution
↓
Monitor / Recover
↓
Mission Knowledge and Operational Evidence
↓
Learning
↓
Improvement / Stronger Future Missions
```

**DOCUMENTED FACT** — `docs/canon/VISION_2050.md`, section **Organizational Evolution**, gives `Vision → Mission → Architecture → Implementation → Validation → Knowledge Preservation → Engineering Intelligence → Genome Evolution → Better Vision`.

**DOCUMENTED FACT** — `docs/architecture/00_PLATFORM_CONSTITUTION.md`, Laws 11 and 12, gives `Architecture → Specification → ADR if required → Implementation → Validation → Knowledge Extraction → Engineer Agent Learning → Release`, and requires both platform capability and learning output.

**DOCUMENTED FACT** — `docs/architecture/CHIEF_AGENT_ARCHITECTURE.md`, sections **Primary Responsibilities** and **Knowledge Lifecycle**, gives `Observe → Understand → Plan → Delegate → Monitor → Recover → Learn → Improve` and `Conversation → Evidence → Candidate Knowledge → Review → Canonical Knowledge → Operational Guidance → Future Automation`.

**DOCUMENTED FACT** — `docs/chief-agent/CHIEF_AGENT_MISSION_SYSTEM.md`, sections **Mission Lifecycle** and **Mission Knowledge**, requires `Created → Planned → Approved → Delegated → Executing → Validating → Completed → Knowledge Extracted → Archived` and requires mission knowledge outputs.

**INFERENCE** — The constitutionally supported production learning cycle is mission-centered, evidence-backed, validation-gated, human-governed, and closed by preserved learning that informs later missions.

**CONFLICT** — Draft Knowledge IR documents specify a more detailed internal pipeline (`Evidence Parser → Compiler → IR → Normalizer → Validator → Relationship Builder → Confidence Calculator → CKM → KP`), but these documents are Draft v1 and cannot redefine the approved higher-level lifecycle.

## 7. Knowledge IR

**DOCUMENTED FACT** — `docs/architecture/knowledge-governance/KNOWLEDGE_INTERMEDIATE_REPRESENTATION.md`, sections **Purpose** and **Core Rule**, defines Knowledge IR as normalized candidate knowledge emitted by compilers before canonical knowledge and prohibits compilers from writing directly to CKM.

**DOCUMENTED FACT** — The same document defines candidate states `extracted`, `normalized`, `needs-review`, `approved`, `rejected`, `merged`, and `superseded`; requires evidence references; assigns normalization and validation responsibilities; and defines compiler metadata.

**DOCUMENTED FACT** — Producers are narrow evidence-specific compilers. Consumers are Normalizer, Validator, Relationship Builder, Confidence Calculator, and ultimately CKM/KP in the draft pipeline.

**INFERENCE** — Ownership belongs to the Knowledge Preservation Platform boundary because the document calls IR the internal contract separating evidence-specific compilers from canonical storage.

**CONFLICT** — The IR contract is Draft v1 while code exists. Its fields and lifecycle are implemented enough to compile some evidence, but constitutional approval of the model is absent.
